Week 4 · Team Challenge · ~80 min

Network Discovery

Four teams, a printer, a PC, and a Raspberry Pi are all on the Auralab network right now. Your job is to find out how many devices are really out there, and build a case for what each one is. A single scan only shows who happens to answer in that moment — so part of the job is knowing how confident you actually are in what you find.

Network: Auralab
Tool: Nmap
Teams: Ghost · Shadow · Fantom · Cipher
Roles: Driver · Navigator (swap every 10 min)
1
Connect & Find Yourself
PASSWD Use the Auralab password given to you in class to connect.
  1. Connect your Kali machine to the Auralab Wi-Fi network.
  2. Open a terminal.
  3. Run ip a to find your own IP address and interface.
  4. Identify your network range. An address like 192.168.1.42 means the network is 192.168.1.0/24.
HINT Write your own IP down before you scan anything. You'll need to cross yourself off the list in Step 3.
2
Run the Ping Sweep

A ping sweep asks every address on the network one question: are you there? It doesn't check ports or services — just who answers.

$ nmap -sn 192.168.1.0/24

This will return a list of IP addresses and MAC addresses. That list is your starting roster.

HINT Record every IP and MAC address on your Network Forensics Worksheet before moving on — you'll need the full list for Step 3.
3
Sort the Noise

Four teams are running Kali on similar hardware at the same time as you. Most of what showed up in your sweep is probably another team's machine — not a hidden device. Cross off your own IP from Step 1, then use the Field Reference below to make a call on everything that's left: another team's Kali box, or something else.

NOTE A guess without a reason isn't a finding. For each host, write down what clue led you there.
4
Find Open Ports

Set aside the hosts you identified as other teams' machines. For each host still unaccounted for, run a default scan and see what's listening.

$ nmap <target-ip>

The pattern of open ports is a fingerprint — see the Field Reference below for what common ports suggest.

5
Re-Sweep for Consistency

A single sweep is a snapshot, not proof. Wait a few minutes, then run the same ping sweep again.

$ nmap -sn 192.168.1.0/24
HINT Did the same hosts answer both times? A host that drops out between sweeps is still worth a note — it may just be filtering ping, not gone.
6
Wrap Up

Talk with your team before you write anything down.

  • Before anything is confirmed: how many devices do you believe are on this network, and how confident are you?
  • What would make you more or less confident in that number?
  • What's the difference between a host that didn't answer and a host that isn't there?
HINT Write your team's answers on the Network Forensics Worksheet.
REF
Field Reference — What Each Clue Tells You
ClueWhat It Tells You
TTLLinux-family systems default to 64. Windows defaults to 128. Network gear and some embedded devices default to 255.
MAC vendor prefixThe first three bytes of a MAC address (the OUI) identify the manufacturer of the network card.
HostnameIf a device broadcasts a name, it can be a direct giveaway.
Open portsPort 22 alone suggests a lean Linux box. Port 631 suggests a printer. Ports 135, 139, and 445 together suggest Windows.
Host countA single sweep only shows who answered right then. A missing device may just be filtering ping requests, not be absent.
