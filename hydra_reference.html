  • What's the target? A real Ubuntu machine on the classroom network, not a simulation.

02
The Correct Hydra Command
Replace TARGET-IP with the address your teacher gave you
$ hydra -l jrogers -P ~/classroom_wordlist.txt ssh://TARGET-IP -t 1 -W 3 -V
FlagWhat it does
-l jrogersSingle username to attack (lowercase L)
-P classroom_wordlist.txtWordlist of passwords — uppercase P required
ssh://TARGET-IPTarget protocol and IP address — a real Ubuntu machine on the classroom network
-t 11 thread — keeps the connection to the target stable
-W 33 second wait between retries — keeps the session stable
-VVerbose — shows each attempt so you know it's running
S1
Hydra printed a help menu / list of options
The command had a syntax error
▾
  • Check lowercase -p vs uppercase -P — they do different things and the wrong one breaks the command silently.
  • Confirm you replaced TARGET-IP with the actual address from your Nmap scan.
  • Verify the wordlist path with ls ~/classroom_wordlist.txt.
S2
classroom_wordlist.txt not found
This wordlist is not pre-installed like rockyou.txt
▾

Your teacher provides this wordlist (USB stick or shared drive). A live USB does not persist files, so copy it into your home directory fresh at the start of every session.

$ ls -lh ~/classroom_wordlist.txt
ℹ
Expected result

A small file, about 2,000 lines. If it's missing, re-copy it before continuing.

S3
[ERROR] 1 target was disabled — too many errors
The target is dropping connections
▾

Hydra is hitting the target too fast. The -t 1 -W 3 flags in the command above fix this — make sure both flags are present. Do not run the default Hydra command without them on this target.

S4
Hydra is running but counting slowly
This is normal — and expected
▾

This target's password is not at the top of the list, and at this lab's pace (one thread, 3 second wait) the crack is designed to take multiple class periods, not minutes. Let it keep running between classes if your setup allows, and pick up where it left off next period.

S5
SSH says Permission denied
Normal Linux behavior, not a bug
▾

Write down the password Hydra prints exactly as shown. When entering it in SSH, nothing appears on screen while you type — type the password and press Enter anyway.

DSC
While You Wait — Team Discussion
Hydra is running. Answer these as a team while it cracks.
What is a dictionary attack? How is it different from a brute force attack that tries every possible character combination?
This lab's wordlist is built from real, frequency-ranked leaked passwords, not guesses. Why do security researchers build wordlists this way instead of trying random character combinations?
Hydra is trying passwords one by one over SSH. What could a sysadmin configure on the server to stop or slow down this exact attack?
We set -t 1 for this lab. Why might a higher thread count against a live SSH service risk dropped connections, lockouts, or look like a denial-of-service attack?
If jrogers had used a strong, random password like X7$kP!2mQw9#rL instead of a common dictionary word, how long would this attack realistically take? What does that tell you about password policy?
